Chora

The route optimisation engine built by Opsi Systems that powers Tramm's planning solver.

Demo

Overview

Chora is Opsi's purpose-built route optimisation solver. It replaces Solo, Opsi's previous solver, and is designed specifically for the complexity of real-world logistics — multiple vehicle types, time windows, capacity constraints, fatigue rules, and loading bay management. Chora runs as the engine behind the Tramm Planner whenever a solver run is triggered.

Supported Job Types

Delivery

Goods are loaded at a depot and delivered to one or more customer sites.

Collection

Goods are picked up from sites and transported to a common offloading site.

Service

A site visit where a service is performed — no goods transfer takes place.

Supported Constraints

Time Windows

  • Job time windows
  • Site operating hours
  • Driver shift windows
  • Overnight & multi-day windows
  • Hard time windows
  • Soft time windows (with configurable penalty)

Capacity

  • Multiple dimensions (mass, volume, pallets, litres, and more)
  • Sum aggregation — total capacity as the sum of all items
  • Max aggregation — capacity based on the single largest item
  • Horse & trailer (articulated vehicles)
  • Rigid vehicles
  • Bulk compartments — single product type per fill
  • Mixed compartments — multiple product types allowed

Restrictions

  • Job / site to vehicle
  • Product to compartment
  • Vehicle to loading dock
  • Custom attributes for resource matching

Fatigue & Breaks

  • Working breaks — triggered after maximum working time (driving + service combined)
  • Driving breaks — triggered after maximum continuous driving time
  • Timed breaks — fixed-time or windowed (e.g. lunch at 13:00, overnight rest)

Loading Bays

  • Time-slotted dock capacity
  • Simultaneous vehicle limit per bay
  • Outbound loading and inbound offloading

Traffic

  • Time-dependent travel times using HERE Maps historical traffic data
  • Matrix caching — first solve downloads data; subsequent solves use the cached matrix

Job Controls

Placement Controls

  • Force exclusive trip — job gets its own route
  • High / low priority
  • Force first stop
  • Force last stop

Grouping Controls

  • Force same trip — multiple jobs on the same route
  • Force different trips — keeps jobs on separate routes (useful for regional planning)
  • Job splitting — oversized jobs automatically split across vehicles

Current Limitations (v1.0)

Single loading site per solve

Each solver run handles one loading site. Use the Solve per Depot option to run independent solves across multiple depots.

No Pickup-and-Delivery (P&D) support

All collections must route to a single common depot. Mixed pickup-and-delivery on the same route is not yet supported.

Manual trailer assignment required

Trailers must be pre-assigned to horses before the solve runs. Automatic trailer assignment is not yet available.
