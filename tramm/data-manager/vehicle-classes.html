Vehicle Classes & Vehicles

A two-layer system — Vehicle Classes define the template, individual Vehicles reference it. The Planner works with classes directly, so named vehicles are optional.

Tramm uses a two-layer model for fleet setup. A Vehicle Class is a template that defines the properties shared by a group of vehicles — their capacity, dimensions, costing structure, and routing profile. An individual Vehicle is a named unit (a specific truck or van) that references a Vehicle Class and inherits all of its properties.

This split means you can plan trips and check capacity without registering every vehicle individually. The Planner works directly against Vehicle Classes, so a Vehicle Class alone is enough for most planning work.

What is a Vehicle Class?

A Vehicle Class is a reusable template that defines the operational properties of a type of vehicle in your fleet. Every vehicle in Tramm must belong to a Vehicle Class, and it inherits that class's capacity, physical dimensions, costing structure, and routing profile.

Think of a Vehicle Class like a manufacturer's specification sheet — drawn up before a fleet rolls off the production line. You define the standard specs once (capacity, dimensions, routing profile, costing) and every vehicle you create from that class inherits them automatically. You only need to record what differs on an individual vehicle: its registration number, home depot, or any spec that genuinely varies from the standard.

This means you can manage a fleet of 50 identical trucks by updating one Vehicle Class, rather than updating each vehicle individually. And for basic trip planning, a Vehicle Class alone is enough — individual vehicles are optional. The Planner can plan and calculate trips using just the class specifications.

Vehicle Classes are enough for trip planning. For basic route planning in the Planner — calculating routes, checking capacity, and building trips — only a Vehicle Class is required. Individual vehicles are optional. You only need individual vehicle records if you want to allocate named vehicles to specific trips, track a particular vehicle, or assign operators by vehicle.

Vehicle Classes are an example of the Classes concept used throughout Data Manager. See the Getting Started guide for a full explanation of how the Classes pattern works.

Rigid

  • Can optionally pull a trailer

Groups & Shared Resources

The Groups field on a Vehicle Class (and on most other Data Manager entities) is not a security or data-isolation feature — it is a way to share resources between planning teams, depots, or regions without duplicating master data.

Groups are arranged in a hierarchy: a higher-level ("primary") group, and one or more subgroups underneath it. For example, a business with planners in Durban, Joburg, and Cape Town might set up:

Example group hierarchy

  • Primary — the top-level group. Anything allocated here is shared with every subgroup below it.
  • Primary › Durban — sees Primary resources, plus anything allocated only to Durban
  • Primary › Joburg — sees Primary resources, plus anything allocated only to Joburg
  • Primary › Cape Town — sees Primary resources, plus anything allocated only to Cape Town

A 30-ton vehicle class shared by every depot should be allocated to Primary only — not to every subgroup individually. It will automatically be usable from Durban, Joburg, and Cape Town. A vehicle that only Joburg owns should be allocated to Primary › Joburg only — Durban and Cape Town will not see it.

The rule: anything allocated to a higher group is shared with everything below it. Anything allocated only to a lower subgroup stays scoped to that subgroup — it is not shared upward or sideways to other subgroups.

Common mistake: ticking every group. Some users select every subgroup on a record, trying to make it "shared for everyone." This is unnecessary and creates ongoing maintenance work — every time a new subgroup is added, you have to go back and manually add it to every existing record. Assign only the highest group that should have access; sharing cascades down automatically.

Groups are not the same as Partitions. Groups are a filtering/organisational tool for sharing resources within your organisation — not a security boundary. Partitions (Settings → Partitions) are for genuinely separate, siloed data — for example, a business operating in two countries that must ensure staff in one country can never see the other country's vehicles, sites, or trips at all. Partitions never share data with each other; Groups share freely within a single partition.

What is a Vehicle?

A Vehicle is an individual record for a specific unit in your fleet — a particular truck, van, or other transport asset. Every Vehicle must reference a Vehicle Class, which determines its capacity, dimensions, costing, and routing profile.

While the Vehicle Class provides the operational blueprint, the individual Vehicle record adds the details that are unique to that specific unit: its registration number, which depot it is based at, which drivers are usually assigned to it, and any regulatory permits it holds.

Two class-level properties can be overridden at the vehicle level if a specific vehicle differs from the rest of its class: operating hours (if this vehicle has different availability) and fuel efficiency (if this vehicle's measured consumption is different from the class default). All other properties — capacity, dimensions, costing, routing class, compartments, and attributes — are fixed at the class level and apply uniformly to every vehicle in the class.

Adding individual vehicles is optional. If your operation plans at the fleet class level — without allocating trips to named vehicles — you do not need to create individual vehicle records. You will still need at least one Vehicle Class per vehicle type you want to plan with.

Adding a Vehicle Class

Follow these steps to create a new Vehicle Class in Data Manager. Set up all your Vehicle Classes before adding individual vehicles.

The Add a VehicleClass form is organised into tabs. Work through them in order:

If vehicles of this class pull trailers, set up the Trailer records in Data Manager first (under Trailers). You cannot assign a trailer that does not already exist.
  1. 1
    Open Data Manager → Vehicle Classes, then click Add
    The form opens on the Basic Info tab.
  2. 2
    Basic Info — enter the identity details
    Enter a Name (required). The ID is auto-generated — leave it. The External ID is also generated automatically, from a template configured in Settings — you don't type this in, but the template can be configured (e.g. group name plus a counter) so the ID matches whatever external system you integrate with. Add a Description if it helps distinguish this class from others. The Groups field assigns this class to a Group for shared-resource organisation — see Groups & Shared Resources below for how this works. Leave blank in a standard single-organisation setup.
  3. 3
    Specification → Type
    Select the vehicle type. None — a standard vehicle that cannot pull a trailer; set capacity on this class as normal. Rigid — a vehicle with its own cargo body that can optionally pull a trailer. Horse — a cab/tractor unit only; selecting Horse disables the Capacity field because a horse's capacity comes entirely from its trailers.
  4. 4
    Specification → Costing
    Set the Fixed, Time, and Distance cost rates for this vehicle type. These are used by the planning solver to optimise route and vehicle selection — not by the Transact Extension. A vehicle with a high fixed cost will be used more sparingly; a high time cost will push the solver towards assigning shorter trips to that class. Leave all at 0 to exclude cost from the planning optimisation.
  5. 5
    Specification → Routing Class
    Select the Routing Class that matches this vehicle type — for example, a profile for heavy vehicles or vehicles with specific road restrictions. Routing Classes are defined in Settings. Most standard vehicle classes do not need one. If left blank, the Planner uses HERE Maps standard routing defaults.
  6. 6
    Specification → Attributes
    Add attribute name/value pairs that describe the capabilities of vehicles in this class — used by the Planner when matching vehicles to jobs and sites via Attribute Rules. Examples: refrigeration_capable = yes, dangerous_goods_certified = true, curtainsider = yes, flatbed = yes. Attribute names must exactly match the names referenced in the Attribute Rules on Product Groups and Site Classes for matching to work correctly.
  7. 7
    Specification → Capacity
    Set the load capacity for this vehicle type. The available dimensions (weight, volume, pallets, or others) depend on what is configured in Settings for your environment — they are not fixed. The Planner checks all dimensions when assigning jobs — a vehicle is considered full as soon as any one dimension reaches its limit. 3D Load Builder: if your Tramm environment includes the 3D Load Builder, you must set Length, Width, and Height here in the Capacity section — the 3D Load Builder uses these dimensions to calculate load placement, not the Physical Size fields. Only set a dimension if the products you plan against also use that dimension; mismatched dimensions can cause unexpected planning results. Note: this field is not available if you selected Horse as the vehicle type — a horse's capacity comes entirely from its trailers.
  8. 8
    Specification → Physical Size
    Set the vehicle's external dimensions: Length, Width, Height, and Mass (the empty vehicle weight — also called tare weight). These values are used in combination with the Vehicle Dimension Limits configured in Settings → Planning Configuration. When the combined physical mass of a vehicle combination exceeds those limits, Trip Builder displays a warning. Physical Size is not used by the 3D Load Builder — for the 3D Load Builder, set Length, Width, and Height in the Capacity tab (Step 7).
  9. 9
    Specification → Trailers
    For Rigid and Horse-type vehicles: assign the default trailer type(s) typically used by vehicles of this class. Trailers must already exist in Data Manager (see callout above). Normally one trailer for a Rigid, one or two for a Horse. Leave blank if this is a None-type class or if trailers are assigned at trip time.
  10. 10
    Specification → Efficiency
    Set the default efficiency figures for this vehicle type: Carbon Emissions (gCO₂/km), Max Payload (kg), and Fuel Consumption (l/100km). Used for cost and sustainability reporting. Can be overridden on individual vehicles.
  11. 11
    Specification → Loading Rate
    Set the default loading time for vehicles of this class. The value is in seconds per unit of the capacity dimension — for example, if your capacity dimension is mass, a value of 5 means 5 seconds per kg; if your dimension is pallets, it means 5 seconds per pallet. This is not a fallback — the vehicle class, site, and product loading rates (wherever each is set) are all added together to produce the total stop duration (also called TAT — turnaround time). The one exception: if a duration is set explicitly on the Job itself, that value replaces the calculated total entirely, instead of adding to it.
  12. 12
    Operating Hours tab
    Set the default operating days and time windows for vehicles of this class. Individual vehicles can override these if needed.
  13. 13
    Attribute Rules tab

    Attribute Rules define the conditions under which vehicles of this class can be matched to jobs, products, and sites. Each rule has four parts:

    • Entity Type — the type of entity the rule checks:
      vehicletrailercompartmentsiteloadingBayregionoperator (driver/person)product
    • Attribute Name — the attribute key to check on that entity type, e.g. refrigeration_required dangerous_goods frozen_goods_product
    • Operator — a logical comparison (not a person):
      noneisSetisNotSetequalsnotEqualsgreaterThanlessThangreaterThanOrEquallessThanOrEqualinnotIn
    • Value — the value to compare against. Leave blank when using isSet or isNotSet. In most real-world setups, attributes work as simple tags — present or not present — so isSet/isNotSet covers the large majority of rules. The numeric comparison operators exist for rarer cases, such as matching on a minimum vehicle length.
    Example rule
    Entity Typeproduct Attribute Namerefrigeration_required OperatorisSet Value— leave blank

    What this does: Only products that have the refrigeration_required attribute will be matched to vehicles of this class. Products without that attribute will be excluded.

    If you leave Attribute Rules empty: The vehicle class has no product restrictions at all — it will accept any product, regardless of what attributes that product has.

  14. 14
    Click Commit
    Saves the Vehicle Class. Close returns without saving.

Adding a Vehicle

Follow these steps to add an individual vehicle record. Remember — individual vehicles are optional. You only need them if you want to allocate named vehicles to trips, track specific units, or assign operators by vehicle.

The Add a Vehicle form is also tab-based. Most vehicles only need Basic Info and Specification → Links filled in — the rest is optional or inherited from the Vehicle Class.

If this vehicle pulls a trailer, set up the Trailer record in Data Manager (under Trailers) before adding the vehicle. You cannot assign a trailer that does not already exist.
  1. 1
    Open Data Manager → Vehicles, then click Add
    The form opens on the Basic Info tab.
  2. 2
    Basic Info — enter the identity details
    Enter the vehicle Name (typically the registration number or fleet number). The External ID is generated automatically from the template set up in Settings — you don't type this in manually. Add a Description if helpful. The Groups field assigns this vehicle to a Group for shared-resource organisation — see Groups & Shared Resources for how this works. Leave blank in a standard single-organisation setup.
  3. 3
    Specification → Links — assign Vehicle Class and Home Site
    Select the Vehicle Class (required) — this sets all the inherited specifications for this vehicle. Select the Home Site — the depot this vehicle starts from and returns to at the end of each trip.
  4. 4
    Specification → Trailers
    For Horse-type vehicles: assign the specific trailer(s) this vehicle typically pulls. The trailer must already exist in Data Manager. These will be pre-selected when the vehicle is allocated to a trip. Leave empty if this vehicle does not pull a trailer, or if trailers are assigned manually at trip time.
  5. 5
    Specification → Efficiency
    Override the efficiency figures for this specific vehicle only if it differs from its Vehicle Class defaults — Carbon Emissions (gCO₂/km), Max Payload (kg), Fuel Consumption (l/100km). Leave blank to inherit from the class.
  6. 6
    Specification → Regulatory Permits
    Add any permits specific to this vehicle — for example, a hazardous goods transport permit or an oversize load permit. The Planner checks these for validity (expiry) when this vehicle is used — configurable to either warn or exclude the vehicle if a permit has expired.
  7. 7
    Default Operators tab
    Assign the default driver(s) for this vehicle. These will be pre-selected when the vehicle is allocated to a trip. Operators must already be set up in Data Manager.
  8. 8
    Operating Hours tab
    Override operating hours only if this vehicle's availability differs from its Vehicle Class default. Leave blank to inherit the class operating hours.
  9. 9
    Click Commit
    Saves the vehicle record. The vehicle is now available for allocation in the Planner.

Tips & Common Mistakes

A few things to keep in mind when setting up Vehicle Classes and Vehicles for the first time.

  • Set up Vehicle Classes before adding individual vehicles. Every vehicle must reference a Vehicle Class. If you try to add vehicles first, you will have nothing to reference. Create all your classes first, then add vehicles.
  • You need at least one Vehicle Class to plan, even if you do not add individual vehicles. If you use an external or hired fleet and do not register individual vehicles, you still need a Vehicle Class for each vehicle type. The Planner works at class level — it cannot plan without one.
  • Setting capacity too low. The Planner will reject any load that exceeds the vehicle's capacity. If orders are consistently failing to plan, check that the capacity set on the Vehicle Class matches the vehicle's actual carrying capacity. A common setup error is entering the tare mass instead of the payload.
  • Setting Length, Width, and Height in Physical Size instead of the Capacity section when using the 3D Load Builder. The 3D Load Builder uses the L/W/H values from the Capacity tab, not from Physical Size. If those Capacity dimensions are missing, the visual will not display. These are set on the Vehicle Class — individual vehicles do not have their own size fields.
  • Setting the same loading rate figure on the vehicle class, site, and product. Because all three add together, entering the same value in more than one place multiplies the effective loading time rather than confirming it — for example, 5 seconds/kg set on all three doesn't mean 5 seconds/kg, it means 15 seconds/kg. Only set a rate at the level(s) where it genuinely needs to apply.
  • Forgetting to assign a Routing Class for specialised vehicles. Standard vehicles on regular road networks do not need a Routing Class — the Planner will use HERE Maps standard routing defaults. But for heavy trucks, vehicles with size or weight restrictions, or other specialist transport types, those defaults may produce inaccurate travel times and distances. Assign the appropriate Routing Class for any non-standard vehicle class.
