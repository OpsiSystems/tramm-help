Vehicle Classes & Vehicles

A two-layer system — Vehicle Classes define the template, individual Vehicles reference it. The Planner works with classes directly, so named vehicles are optional.

Tramm uses a two-layer model for fleet setup. A Vehicle Class is a template that defines the properties shared by a group of vehicles — their capacity, dimensions, costing structure, and routing profile. An individual Vehicle is a named unit (a specific truck or van) that references a Vehicle Class and inherits all of its properties.

This split means you can plan trips and check capacity without registering every vehicle individually. The Planner works directly against Vehicle Classes, so a Vehicle Class alone is enough for most planning work.

Vehicle Class — the template
Defines shared properties for a group of vehicles.
  • Capacity (weight, volume, units)
  • Physical dimensions
  • Costing structure
  • Routing class
  • Operating hours (default)
  • Compartments, attributes, and more
Vehicle — the individual unit
References a Vehicle Class and adds identity-level detail.
  • Registration or identifier
  • Home site (depot)
  • Default operators and trailers
  • Regulatory permits
  • Optional overrides: operating hours, efficiency

What is a Vehicle Class?

A Vehicle Class is a reusable template that defines the operational properties of a type of vehicle in your fleet. Every vehicle in Tramm must belong to a Vehicle Class, and it inherits that class's capacity, physical dimensions, costing structure, and routing profile.

Think of a Vehicle Class the way you would think of a vehicle model — for example, "10-tonne rigid truck" or "refrigerated van". All the trucks of that model have the same load capacity and the same cost structure. You define those properties once on the class, and every vehicle of that type automatically has them.

The properties set on a Vehicle Class are fixed. Most cannot be changed on individual vehicles — the ones that can be overridden (operating hours and fuel efficiency) are noted in the fields sections below.

Vehicle Classes are enough for trip planning. For basic route planning in the Planner — calculating routes, checking capacity, and building trips — only a Vehicle Class is required. Individual vehicles are optional. You only need individual vehicle records if you want to allocate named vehicles to specific trips, track a particular vehicle, or assign operators by vehicle.

Vehicle Classes are an example of the Classes concept used throughout Data Manager. See the Getting Started guide for a full explanation of how the Classes pattern works.

Vehicle Class Fields

Fields are grouped by function below. Fields marked Required must be filled in before saving. All others are optional but recommended for accurate planning and costing.

Field Status Description
Identity

Name

 Required

A descriptive name for this class, such as "10T Rigid" or "Refrigerated Van". This name appears in the Planner when selecting a vehicle type for a trip.

Type

 Required

The vehicle category — for example, Truck, Van, or Motorbike. This is selected from a fixed list (EVehicleType) and affects how the Planner handles the vehicle.
Capacity

Capacity

 Required

How much this vehicle can carry, expressed as weight, volume, and/or units. This is the value the Planner checks when loading orders onto a trip — if an order's size exceeds the remaining capacity, the Planner will not add it to that trip.

Set all three measures that are relevant to your operation. If you only use weight-based planning, set weight only. If you use both weight and volume, set both — the Planner enforces whichever limits are set.

Compartments

 Optional

Sub-sections within the vehicle that have separate capacity limits — for example, a chilled compartment and an ambient compartment on a refrigerated truck. Each compartment has its own capacity settings.

Only needed if the vehicle carries loads that must be physically separated or have different temperature requirements.

Max Trailer Count

 Optional

The maximum number of trailers this class of vehicle can pull. Used for planning multi-trailer operations.
Physical Dimensions

Length

 Optional

The overall length of the vehicle. Required if the 3D Visualiser is enabled — the visualiser uses these measurements to render an accurate representation of the vehicle and its load.

Width

 Optional

The overall width of the vehicle. Required for 3D Visualiser rendering.

Height

 Optional

The overall height of the vehicle. Required for 3D Visualiser rendering.

Mass

 Optional

The unladen (tare) mass of the vehicle. Used in conjunction with the load capacity for gross vehicle mass calculations.

Physical dimensions are set on the Vehicle Class only. Individual vehicles do not have their own dimension fields — they inherit these values from their class.
Planning & Routing

Routing Class

 Optional

The routing profile the Planner uses when calculating travel times and distances for vehicles of this class. Different vehicle types may have different speed profiles, restricted roads, or legal requirements — these are encoded in Routing Classes.

If left blank, the system uses the Default routing profile, which may not accurately reflect the real travel behaviour of specialised vehicles such as heavy trucks or hazmat carriers.
Time & Availability

Operating Hours

 Optional

The default hours that vehicles of this class are available to be planned. For example, a day-shift fleet might be available 06:00–18:00. The Planner uses these hours to constrain when trips can start and end.

Can be overridden on individual vehicles if a specific vehicle has different availability from the rest of its class.
Costing

Fixed Cost

 Optional

A flat cost applied per trip for vehicles of this class, regardless of distance or duration — for example, a daily hire fee or a fixed trip charge.

Distance-Based Cost

 Optional

A cost rate applied per kilometre (or per unit of distance). Used to calculate the variable distance component of trip cost.

Time-Based Cost

 Optional

A cost rate applied per unit of time — for example, per hour of trip duration. Used when driver time or vehicle utilisation by the hour forms part of the costing model.
Other

Efficiency

 Optional

Fuel efficiency metrics for vehicles of this class — for example, litres per 100 km. Used in fuel cost calculations and FleetVision reporting.

Can be overridden on individual vehicles if a specific vehicle's measured efficiency differs from the class default.

Attributes

 Optional

Custom key-value attributes that apply to all vehicles of this class. Attributes are inherited by every vehicle in the class and can be used for filtering, reporting, or custom business logic.

What is a Vehicle?

A Vehicle is an individual record for a specific unit in your fleet — a particular truck, van, or other transport asset. Every Vehicle must reference a Vehicle Class, which determines its capacity, dimensions, costing, and routing profile.

While the Vehicle Class provides the operational blueprint, the individual Vehicle record adds the details that are unique to that specific unit: its registration number, which depot it is based at, which drivers are usually assigned to it, and any regulatory permits it holds.

Two class-level properties can be overridden at the vehicle level if a specific vehicle differs from the rest of its class: operating hours (if this vehicle has different availability) and fuel efficiency (if this vehicle's measured consumption is different from the class default). All other properties — capacity, dimensions, costing, routing class, compartments, and attributes — are fixed at the class level and apply uniformly to every vehicle in the class.

Adding individual vehicles is optional. If your operation plans at the fleet class level — without allocating trips to named vehicles — you do not need to create individual vehicle records. You will still need at least one Vehicle Class per vehicle type you want to plan with.

Vehicle Fields

Fields marked Overridable can override the value set on the Vehicle Class for this specific vehicle. Leave them blank to inherit the class value.

Field Status Description

Vehicle Class

 Required

The Vehicle Class this vehicle belongs to. This is the only required field on a vehicle record. It determines the vehicle's capacity, physical dimensions, costing structure, routing profile, and default operating hours.

Once saved, changing the Vehicle Class on a vehicle record will change its capacity and costing. Do this carefully.

Registration / Name

 Optional

The registration plate or internal identifier for this vehicle. This is the label that appears when selecting or allocating a specific vehicle in the Planner or Execution Manager.

Home Site

 Optional

The depot or site this vehicle is based at. The Planner can use the home site as the vehicle's start and end point when building trips.

Default Operators

 Optional

The driver or drivers usually assigned to this vehicle. Setting default operators saves time when allocating a trip — the usual driver is pre-filled rather than requiring manual selection each time.

Default Trailers

 Optional

Trailers that are usually attached to this vehicle. Like default operators, these are pre-filled when the vehicle is allocated to a trip.

Operating Hours

 Overridable

If this vehicle has different availability from the rest of its class — for example, a vehicle reserved for night-shift work — set its specific operating hours here. If left blank, the vehicle uses the operating hours defined on its Vehicle Class.

Efficiency

 Overridable

If this vehicle's actual fuel consumption is measurably different from the class default — for example, an older vehicle with higher fuel use — set a vehicle-specific efficiency here. If left blank, the vehicle uses the efficiency defined on its Vehicle Class.

Regulatory Permits

 Optional

Vehicle-specific permits — for example, a hazardous materials transport permit, an oversize load permit, or a border crossing permit. These are recorded at the individual vehicle level because they apply to the specific unit, not to the whole class.

Adding a Vehicle Class

Follow these steps to create a new Vehicle Class in Data Manager. Set up all your Vehicle Classes before adding individual vehicles.

  1. 1

    Open Data Manager and go to Vehicle Classes

    From the main navigation, open Data Manager. Select Vehicle Classes from the entity list on the left.

  2. 2

    Click Add

    Click the Add button in the toolbar. The new Vehicle Class form will open.

[Screenshot: Add Vehicle Class form showing Name, Type, and Capacity fields]
  1. 3

    Enter a name and select the vehicle type

    Give the class a clear, descriptive name — for example, 10T Rigid or Refrigerated Van. Select the appropriate Type from the dropdown (for example, Truck, Van, or Motorbike).

  2. 4

    Set the capacity

    Enter the vehicle's carrying capacity. You can set weight, volume, and units independently — set whichever measures your operation uses. The Planner enforces every limit you set, so if you set both weight and volume, a load is rejected if it exceeds either limit. If you only plan by weight, leave volume and units blank.

  3. 5

    Set physical dimensions (if using the 3D Visualiser)

    If your Tramm environment uses the 3D load visualiser, enter the vehicle's Length, Width, and Height. These are required for the visualiser to render the vehicle correctly. Mass is optional but useful for gross vehicle mass calculations. If you are not using the 3D Visualiser, you can skip this step.

  4. 6

    Assign a Routing Class

    Select the Routing Class that best matches this vehicle type. The Routing Class controls how the Planner calculates travel times and routes — for example, heavy vehicles may be restricted from certain roads or have lower average speeds. If your fleet is standard and no specialist routing is needed, you may leave this blank and the system will use the Default routing profile.

  5. 7

    Set operating hours (if different from company defaults)

    If vehicles of this class have specific availability windows — for example, they only operate 06:00–14:00 — enter those hours here. If the class follows the same hours as the rest of your operation, you can leave this blank and configure operating hours at the company or site level instead.

  6. 8

    Save

    Click Save (or Commit depending on your form layout). The Vehicle Class is now available in the Planner and can be referenced when adding individual vehicles.

Adding a Vehicle

Follow these steps to add an individual vehicle record. Remember — individual vehicles are optional. You only need them if you want to allocate named vehicles to trips, track specific units, or assign operators by vehicle.

  1. 1

    Open Data Manager and go to Vehicles

    From the main navigation, open Data Manager. Select Vehicles from the entity list.

  2. 2

    Click Add

    Click the Add button in the toolbar to open the new Vehicle form.

  3. 3

    Select a Vehicle Class

    This is the only required field. Select the Vehicle Class this vehicle belongs to. This determines the vehicle's capacity, physical dimensions, costing, and routing profile. Make sure the correct Vehicle Classes are set up before adding vehicles.

[Screenshot: Add Vehicle form with Vehicle Class field highlighted]
  1. 4

    Enter the registration or identifier

    Enter the vehicle's registration plate or an internal code. This is the label used to identify this vehicle in the Planner and Execution Manager.

  2. 5

    Set the home site (if applicable)

    Select the depot or warehouse this vehicle is based at. If the vehicle operates from a single site, setting the home site lets the Planner use it as the vehicle's default start and end location.

  3. 6

    Assign default operators or trailers (if applicable)

    If a specific driver is normally assigned to this vehicle, add them as a Default Operator. If a trailer is normally attached, add it as a Default Trailer. These defaults speed up trip allocation but can always be changed when building a trip.

  4. 7

    Override operating hours only if needed

    Leave this blank unless this specific vehicle has different availability from the rest of its class. If you set operating hours here, they will override the class-level hours for this vehicle only. In most cases, operating hours should be set at the class level rather than on individual vehicles.

  5. 8

    Save

    Click Save. The vehicle is now available for allocation in the Planner and Execution Manager.

Tips & Common Mistakes

A few things to keep in mind when setting up Vehicle Classes and Vehicles for the first time.

  • Set up Vehicle Classes before adding individual vehicles. Every vehicle must reference a Vehicle Class. If you try to add vehicles first, you will have nothing to reference. Create all your classes first, then add vehicles.
  • If you plan at the class level, you still need at least one Vehicle Class per vehicle type. Even if you do not register individual vehicles, the Planner needs Vehicle Classes to know the capacity and routing profile for each type of vehicle in your operation.
  • Setting capacity too low. The Planner will reject any load that exceeds the vehicle's capacity. If orders are consistently failing to plan, check that the capacity set on the Vehicle Class matches the vehicle's actual carrying capacity. A common setup error is entering the tare mass instead of the payload.
  • Not setting physical dimensions when the 3D Visualiser is enabled. If your Tramm environment includes the 3D load visualiser, it requires Length, Width, and Height on the Vehicle Class to render correctly. If these are missing, the visualiser will not display the vehicle. Dimensions are set on the class — individual vehicles do not have their own size fields.
  • Forgetting to assign a Routing Class for specialised vehicles. If no Routing Class is set, the Planner uses the Default routing profile, which is calibrated for standard road vehicles. For heavy trucks, vehicles with road restrictions, or specialist transport types, the Default profile may produce inaccurate travel times and distances. Assign the appropriate Routing Class when setting up each Vehicle Class.
