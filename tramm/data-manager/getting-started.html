Getting Started with Data Manager

Learn the Classes and Groups concept, then follow the recommended setup sequence to get your reference data in place.

Data Manager is where you set up all the reference data that the rest of Tramm relies on — vehicles, sites, products, clients, and more. Before you start adding data, there are two things worth understanding: the Classes and Groups concept, and the recommended setup order.

Classes and Groups — the Template Concept

In Data Manager, most entities come in pairs: a Class (or Group) and the individual entity that belongs to it. The Class is the template — you define shared properties once on the Class, and every entity of that Class inherits them automatically. You only need to set individual values on an entity when it differs from its class.

Think of a Vehicle Class, Site Class, or Product Group as a specification sheet — you define the standard specifications once, and every entity you create from that template inherits them automatically. You only need to record what differs on an individual entity: a vehicle's registration number, a site's address, or a product's exact dimensions. The same principle applies across all three pairs — one specification sheet, many instances, with individual variations noted only where they exist.

Products take this one step further — a Product can belong to more than one Product Group simultaneously. A refrigerated hazardous item can belong to both a "Frozen Goods" group and a "Hazardous Materials" group at the same time, inheriting the rules and restrictions of both. For Vehicle Classes and Site Classes, each entity belongs to exactly one class.

Overrides — when an individual entity differs from its Class or Group

If a value is left blank (or set to zero for durations), the system automatically uses the Class or Group value as the default. You only need to fill in a value on the entity if it genuinely differs. This means you can set up 50 sites in a "Retail Delivery" class and only override the operating hours for the two sites that have unusual hours — the other 48 inherit the class default without any extra work.

Note: for Products, the pattern works slightly differently. A Product Group provides shared rules (restrictions, variance tolerance) rather than values to inherit — the Product itself defines its own physical specifications. See the Product Groups, Products & Transport Units guide for details.

The table below summarises what is fixed at Class level versus what can be overridden on individual entities.

Entity Fixed at Class / Group level Defined or overridden on individual entities
Vehicle Inherited Type, Capacity (mass / volume / units), Physical Size (length / width / height), Compartments, Costing Overridable Operating Hours, Fuel Efficiency
Site Inherited Type, Attribute restrictions Overridable Operating Hours, Entry Duration, Exit Duration, Loading Rate
Product Inherited Transport restrictions (vehicle / compartment requirements) Size (mass / volume / units), Loading Rate, Stackability — set directly on the Product itself; there is no Group-level default being overridden here
A Vehicle Class on its own is enough for basic trip planning in the Planner. Individual vehicles are optional — you only need to add them if you want to track specific vehicles, assign operators, or allocate named vehicles to trips.

Attributes & Attribute Rules — the Matching Concept

Alongside Classes and Groups, one more concept is worth understanding before you start entering data: Attributes and Attribute Rules. These appear throughout Data Manager — on Vehicle Classes, Trailers, Sites, Site Classes, and Product Groups — and are used to match the right resources to the right jobs.

An Attribute is a tag you attach to an entity — for example, tagging a vehicle as frozen. Most attributes work this way: as a simple tag that is either present or not present, not as a value to compare. An Attribute Rule is a rule elsewhere in the system that looks for that tag to decide whether a match is allowed — for example, a product's attribute rule might require a frozen vehicle. Matching tags include or exclude combinations depending on where the rule is set up.

You don't need to set up Attributes and Attribute Rules before adding any data — but knowing they exist up front helps you recognise them when you reach the Attributes tab on each entity, rather than being surprised by an unfamiliar field.

3D Visualiser — When Dimensions Matter

If your organisation uses the 3D Visualiser in the Planner — which shows how cargo is loaded into a vehicle — you need to make sure dimensions are set up correctly. The visualiser uses Length, Width, and Height only — not mass. These must be set on the Vehicle Class Capacity (not on individual vehicles, and not on Physical Size) and on the Product record. Without these three dimensions, the 3D Visualiser cannot render the load correctly. Mass is used separately, for Stackability calculations.

Recommended Setup Sequence

Follow this order when setting up Data Manager for the first time. Each step builds on the one before it — but this is a recommendation, not a strict requirement. The right order really depends on your operation (for example, if you use home sites, you may want Sites in place before Vehicles), and Data Manager lets you create a missing prerequisite record inline while filling in a dependent form, so it's rarely a problem if you tackle things out of order.
