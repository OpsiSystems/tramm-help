Getting Started with Data Manager

Learn the Classes and Groups concept, then follow the recommended setup sequence to get your reference data in place.

On this page

  • Classes & Groups
  • 3D Visualiser
  • Setup Sequence
  • Where to Next

Data Manager is where you set up all the reference data that the rest of Tramm relies on — vehicles, sites, products, clients, and more. Before you start adding data, there are two things worth understanding: the Classes and Groups concept, and the recommended setup order.

Classes and Groups — the Template Concept

This is the most important concept in Data Manager. Several entity types in Tramm follow a two-layer pattern: a Class (or Group) acts as a template, and individual entities are based on that template.

The Class or Group (template)

Defines shared properties once — type, capacity, dimensions, operating hours, restrictions, and more.

  • Vehicle Class — capacity, dimensions, costing
  • Site Class — operating hours, entry/exit durations
  • Product Group — shared attributes and restrictions

The individual entity (inherits from the template)

References its Class or Group and automatically inherits all its shared properties. You only need to enter the details that are unique to this specific entity.

  • Vehicle — registration, home site, operator
  • Site — address, coordinates, client link
  • Product — name, code, loading rate

The benefit is that you define shared properties once on the Class or Group, and all entities in that class inherit them automatically. You do not need to re-enter the same capacity, dimensions, or operating hours for each individual vehicle or site.

[Screenshot: Vehicle Classes list in Data Manager showing multiple classes with their type, capacity, and dimensions columns]

Overrides — when an individual entity differs from its class

Some properties can be overridden at the individual entity level. For example, a specific vehicle may have different operating hours from its Vehicle Class, or a specific site may have a different entry duration from its Site Class. When the system needs a value, it uses the entity's own value if one is set — otherwise it falls back to the Class or Group value.

[Screenshot: A Vehicle record showing the Operating Hours field set at the vehicle level, overriding the value inherited from the Vehicle Class]

The table below summarises what is fixed at Class level versus what can be overridden on individual entities.

Entity Fixed at Class level — cannot be overridden Can be overridden on individual entities
Vehicle Inherited Type, Capacity (weight / volume / units), Physical Size (length / width / height), Compartments, Costing Overridable Operating Hours, Fuel Efficiency
Site Inherited Type, Attribute restrictions Overridable Operating Hours, Entry Duration, Exit Duration, Loading Rate
Product Inherited Transport restrictions (vehicle / compartment requirements) Overridable Size (weight / volume / units), Loading Rate, Stackability
A Vehicle Class on its own is enough for basic trip planning in the Planner. Individual vehicles are optional — you only need to add them if you want to track specific vehicles, assign operators, or allocate named vehicles to trips.

3D Visualiser — When Dimensions Matter

If your organisation uses the 3D Visualiser in the Planner — which shows how cargo is loaded into a vehicle — you need to make sure dimensions are set up correctly. Physical dimensions (length, width, height) must be set on the Vehicle Class, not on individual vehicles. Product dimensions (size — weight, volume, units) must be set on the Product record. Without these values, the 3D Visualiser cannot render the load correctly.

Recommended Setup Sequence

The steps below represent the recommended order for setting up Data Manager. It is not a strict requirement — you can revisit any step later — but following this sequence means you will have the right dependencies in place before you need them.

1

Settings

Set up your site address preference and other system options. Each user can configure their own preferences. For a full list of settings that affect Data Manager, see the Data Manager overview.

2

Vehicle Classes

Define the templates for your vehicles: type, capacity, physical dimensions, compartments, costing, and routing class. If you are using the 3D Visualiser, set physical dimensions (length, width, height) here. All vehicles will inherit these values from their class.

3

Vehicles Optional

Add individual vehicles if you need to track or assign specific vehicles by name or registration. Each vehicle must reference a Vehicle Class. If you only need to plan trips by vehicle type, Vehicle Classes are sufficient — individual vehicle records are not required.

4

Site Classes

Define templates for your locations — standard operating hours, entry and exit durations, and any attribute restrictions shared across similar sites. Every site must reference a Site Class.

5

Sites

Add your depots, warehouses, distribution centres, and delivery points. Each site references a Site Class and inherits its operating hours and durations. Override operating hours or durations on individual sites where needed.

6

Product Groups

Create groupings for your products that share transport restrictions — for example, refrigerated goods, hazardous materials, or standard dry cargo. Every product must reference a Product Group.

7

Products

Add your transportable goods with their sizes (weight, volume, units), loading rates, and stackability rules. Each product references a Product Group. If using the 3D Visualiser, ensure size values are set here.

8

Optional setup As needed

Add these entities when your operation requires them: Clients (for customer relationship tracking and order cutoff schedules), Transporters (for external carriers), Fleets (for grouping vehicles by home site), Operators (for individual driver tracking), Regions & Lanes (for geographic groupings or lane-based tariffs), and Transport Units (for container type tracking).

9

Financial setup Transact Extension only

Set up Master Charges, Charge Categories, and Tax Types only if you are using Tramm for costing, billing, or tariff management. These are part of the Transact Extension and are not visible to all users.
