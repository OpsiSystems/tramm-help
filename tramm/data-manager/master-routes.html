Master Routes

What is a Master Route?

A Master Route is a saved, reusable sequence of stops that a trip can be built from. Instead of planning a recurring route from scratch every day, you set it up once and reuse it — which makes planning faster and more consistent.

Master Routes are built and maintained in their own app, Master Route Builder — a separate app from the Planner, with its own permission. Trips built later stay linked back to the Master Route they came from, so you can always see which template a trip was based on.

Legs

The individual stops that make up a route, in order. If every leg has both an arrival and departure time set, Tramm treats those times as fixed and won't recalculate them. If any leg is missing a time, Tramm ignores the fixed times altogether and works out travel times for the whole trip the normal way instead.

Master Route Sets

A named group of Master Routes, used to manage several routes together and, optionally, to generate trips from them automatically on a schedule. See Master Route Sets & Scheduling.

Master Routes work well for regular, predictable movements — a daily delivery run, a depot loop, a fixed cross-border corridor. They're the wrong tool for one-off or constantly-changing routes — for those, build the trip manually instead.

Route Kinds

Every Master Route has a Kind, and the Kind you choose genuinely changes how the route behaves — it's not just a label. There are four:

Standard

Built around jobs. When a trip is built from a Standard route, job stops are added into the route's sequence, and any stop that ends up with no job attached is dropped.

Example: a daily delivery route where the same customers are usually visited in the same order, but the exact stop list depends on which jobs came in.

Stop-Only

Operational stops with no jobs attached at all — jobs are never added to a Stop-Only route. The stop list stays exactly as configured.

Example: a vehicle inspection loop, or a depot run that doesn't deliver or collect anything.

Tour

Has a fixed start site and end site, with one or more tour stops in between. When applied to a trip, the tour's stops are inserted between two existing stops that match its start and end sites — the sequence isn't freely rearranged.

Example: a cross-border run with mandatory customs and rest stops in a fixed order.

Ad Hoc Tour

Also has a fixed start and end site, and — like Tour — doesn't get an automatic "return to home" stop added, since the end site is already part of the route. Unlike Tour, it isn't picked up by the automatic tour-splicing action in Planner.

Note: this Kind exists in Tramm but isn't widely documented yet — check with your implementation team on the intended use case for your environment before relying on it.

Automated scheduling (see Master Route Sets & Scheduling below) only works with Stop-Only routes. Standard, Tour, and Ad Hoc Tour routes can still be applied manually in Planner, but they are not picked up by scheduled, automatic trip generation.

Creating a Master Route

A Master Route needs a few things in place before it's useful. Here's what to check first, then how to build one.

Before you start
NeededNotes
Sites RequiredEvery stop (leg) on the route must point to a Site that already exists in Data Manager.
Vehicle Classes / Vehicles OptionalOnly needed if you plan to restrict the route to specific vehicle classes or specific vehicles. By default, any vehicle can be used.

Lanes, Products, Transporters, and Operators are not prerequisites for a Master Route — the route itself has no relationship to any of them.

LegsThe ordered list of stops. Add a customer from the dropdown for each leg, in the order the route should visit them.

A route needs at least one leg before it can be saved and used — the Legs tab is enforced as required.

Editing a Master Route

You'll typically come back and edit a route when something operational changes — not because of a formal approval process, since there isn't one.

Common reasons to edit
  • A customer is added or removed
  • A site's operating hours or requirements change
  • Stops were configured in the wrong order
  • The required vehicle class changes
If…Then…
A route is editedThe change affects future trips only — trips already built from this route are not changed.
A route is savedIt's available immediately in Planner — there is no separate publish or approval step.
A route is used in a Master Route SetThe change affects future automated trip generation from that set (see Master Route Sets & Scheduling).
A non-admin tries to edit a routeEditing may be restricted, depending on their role.

Using Master Routes in Planning

Applying a Master Route to a trip gives the planner a head start — the stop sequence comes pre-filled, and they can review it before committing.

  1. 1
    Open the Planner
  2. 2
    Start a new trip, or select a job that needs routing
  3. 3
    Select "Build Trip from Master Route"
  4. 4
    Choose the Master Route from the list
    Its stop sequence is imported into the trip.
  5. 5
    Review, then commit
    Check the imported stops before saving — you can still adjust the trip afterwards unless your organisation restricts this.
How each Route Kind behaves once applied
Route KindWhat happens in the trip
StandardJob stops are added in; the planner can still adjust the stop sequence.
Stop-OnlyOnly the operational stops appear — no jobs are attached.
TourIts stops are spliced in between a matching start/end pair already in the trip — the sequence isn't freely rearranged.
Ad Hoc TourFixed start/end, but not picked up by the automatic tour-splicing action — check with your implementation team on how this should be applied in your environment.

A trip built from a Master Route is a snapshot, not a live link. If you edit the Master Route afterwards, trips already built from it stay exactly as they were.

Master Route Sets & Scheduling

A Master Route Set is a named group of Master Routes. On its own, it's just a way to organise related routes together — but it can also drive automatic trip generation.

The Set's four tabs
TabWhat you do there
Basic InfoName, ID, Description, and Group access.
Master RoutesWhich routes belong to this set.
SchedulesWhen (and whether) trips should be generated from this set automatically — only applies if automatic generation is configured. A schedule is a start time plus a recurring calendar pattern, not a simple day-of-week toggle.
Custom FieldsAny organisation-specific fields your implementation has added — this tab appears on every Tramm form, not just Master Route Sets.
Automatic trip generation

Tramm can generate trips from a Master Route Set automatically, on a schedule, without anyone doing it manually. This is a scheduled background task — some teams refer to it informally as "the Worker," but that's a descriptive nickname used in training material, not the literal name of a button or menu item, and it's a different thing from any other background component in Tramm that might share that name.

If…Then…
The scheduled time arrivesThe task loads the assigned Route Set and reads the current state of each Master Route in it.
A route in the set only just changedThe change is picked up automatically — the set always reads the route's current state, not a stored copy.
A route in the set is not Stop-OnlyIt is skipped — automatic generation only works for Stop-Only routes.
You need trips generated right nowUse the manual "Build Trips From Selected Set" action instead of waiting for the schedule.

Automated trip generation does not optimise, reorder, or "fix" a route. It builds trips exactly as the Master Route and Route Set are configured — and it never creates new Master Routes on its own. Nothing changes until the schedule next runs, or someone triggers it manually.

Troubleshooting

Common issues and where to look first.

If…Then check…
The route won't saveAll mandatory fields are complete, and the route has at least one leg.
The route isn't showing up in PlannerThe Groups on the route match the user's access, and any filters applied in Planner.
Stops are in the wrong orderThe sequence on the Legs tab in Master Route Builder — fix it there, not in an already-built trip.
A route change isn't showing up in automated tripsWhether the route is Stop-Only, whether it's in a Route Set, and whether the schedule (or a manual trigger) has actually run since you made the change.

Best Practice

A few habits that keep Master Routes reliable as your operation grows.

  • Name routes consistently. Include the region or depot and the direction of travel, so planners can find the right route without opening it.
  • Check sites are active and service times are realistic before relying on a route day to day.
  • Limit editing rights to a small group. A route in active use affects every trip built from it going forward.
  • Don't use a Master Route for non-standard or constantly-changing work. If the stop sequence changes regularly or the job needs a flexible approach, build the trip manually instead.
