Trailers

Passive transport assets pulled by Horse or Rigid type vehicles. Set up Trailers before creating the Vehicle Classes and Vehicles that reference them.

A Trailer is a passive transport asset — it has no engine of its own and must be pulled by a Horse or Rigid type vehicle. A Rigid vehicle can carry its own load and still tow a trailer, so trailers are not limited to Horse-type tractors. In Tramm, Trailers are set up as individual records in Data Manager, and then referenced on Vehicle Classes and individual Vehicles that typically use them.

Not every operation uses Trailers. They are only needed if your fleet includes Horse or Rigid type vehicles that pull interchangeable trailers, and you want Tramm to track those trailers, manage their capacity, or pre-assign them to vehicles and trips.

Where Trailers are referenced
Once created, a Trailer record can be assigned in two places:
  • Vehicle Class — default trailer type(s) for all vehicles of that class
  • Vehicle — default trailer(s) for a specific named vehicle
In both cases, the Trailer must already exist in Data Manager before it can be assigned.
What a Trailer record defines
Each Trailer record holds the properties specific to that trailer:
  • Load capacity (mass, volume)
  • Physical dimensions
  • Compartments (for multi-temp or segregated loads)
  • Costing structure
  • Regulatory permits
  • Attribute Rules (vehicle compatibility)

Set up Trailers first. If your Vehicle Classes or Vehicles reference trailers, create all Trailer records in Data Manager before you add those Vehicle Classes or Vehicles. You cannot assign a trailer that does not already exist.

What is a Trailer?

In Tramm, a Trailer is a standalone master data record representing a physical trailer unit in your fleet. It is a passive asset — it cannot move on its own, and it is always used in conjunction with a Horse or Rigid type vehicle.

Horse-type vehicles (truck-tractors) and towing-capable Rigid vehicles can both be paired with different trailers depending on the load. This flexibility is a key reason for managing trailers as separate records: the same vehicle can pull a flatbed one day and a refrigerated trailer the next. By setting up each trailer as its own record, Tramm can track capacity and attributes at the trailer level — not just at the vehicle level.

When a trip is planned using a Horse vehicle, the trailer's capacity and attributes are factored in alongside the vehicle's. If the trailer has defined compartments, those compartments are available for load planning just as they would be on a rigid vehicle.

Trailers are relevant for both Horse-type and Rigid-type vehicle classes. A Rigid vehicle carries its own load and can also tow a trailer — it is not limited to a fixed body. Only vehicles set up as None type have no trailer capability at all. See Vehicle Classes & Vehicles for an explanation of the None, Rigid, and Horse distinction.

Compartments vs Simple Capacity

A trailer can be set up with either a simple total capacity, or with multiple named compartments each having their own capacity — but not both at the same time. Choose the approach that matches how this trailer is actually used.

Use simple Capacity when the trailer carries a single type of load and there is no need to separate cargo into distinct sections. Set the total mass, volume, and/or unit capacity on the trailer record. The Planner treats the trailer as a single load space.

Use Compartments when the trailer has physically or logically separate sections — for example, a multi-temperature trailer with a frozen compartment and a chilled compartment, or a tanker with multiple chambers. Each compartment has its own capacity, and can also have its own attributes and restrictions. When compartments are defined and enabled, the simple Capacity field on the trailer is cleared and ignored — the compartment capacities are used instead.

Compartment planning on trailers works the same way as on Vehicle Classes. If you have already set up compartments on a Vehicle Class, the same logic applies here. You cannot use both simple Capacity and Compartments on the same trailer record — the system uses one or the other based on whether compartments are defined.

Attribute Rules

Attribute Rules on a Trailer define the conditions under which this trailer can be used — for example, restricting it to vehicles with a specific permit, or to products that meet a particular requirement. They work in exactly the same way as Attribute Rules on Vehicle Classes.

Each rule has four parts:

  • Entity Type — the type of entity the rule checks against:
    vehicletrailercompartmentsiteloadingBayregionoperator (driver/person)product

  • Operator — a logical comparison:

If Attribute Rules are left empty: The trailer has no restrictions — it can be assigned to any vehicle or used with any product, regardless of attributes.

Adding a Trailer

Follow these steps to create a new Trailer record in Data Manager. Complete this before setting up the Vehicle Classes or Vehicles that will reference this trailer.

  1. 1
    Open Data Manager → Trailers, then click Add
    The form opens on the Basic Info tab.
  2. 2
    Basic Info — enter the identity details
    Enter a Name (required) — this is how the trailer will appear when assigning it to a Vehicle Class or Vehicle. The External ID is generated automatically from the template set up in Settings — you don't type this in, but you can configure how it's built so it lines up with your external systems. Add a Description if it helps distinguish this trailer from others of the same type. The Groups field assigns this trailer to a Group for shared-resource organisation — see Groups & Shared Resources for how this works. This is different from Settings → Partitions. Leave blank in a standard single-organisation setup.
  3. 3
    Specification → Costing
    Set the Fixed, Time, and Distance cost rates if trailer costs are tracked separately from the towing vehicle. Leave all at 0 if your organisation does not track trailer-level costing in Tramm, or if costs are already accounted for on the Vehicle Class.
  4. 4
    Specification → Attributes
    Add attribute name/value pairs that describe the capabilities of this trailer — used by the Planner when matching trailers to jobs, vehicles, and sites via Attribute Rules. Examples: refrigerated = yes, curtainsider = true, hazmat_certified = yes. Attribute names must exactly match the names referenced in Attribute Rules on Vehicle Classes and Product Groups for matching to work correctly.
  5. 5
    Specification → Compartment Planning
    Decide whether this trailer uses compartments or simple capacity. If the trailer carries a single load type — leave compartments off and proceed to the Capacity step. If the trailer has separate sections (e.g. frozen and chilled) — enable compartments, define each compartment with its own name and capacity, and skip the simple Capacity step. You cannot use both simultaneously.
  6. 6
    Specification → Capacity (if not using compartments)
    Set the total load capacity for this trailer — mass (kg), volume (m³), and/or units, depending on what dimensions your operation plans against. Skip this step if you have set up compartments — compartment capacities are used instead.
  7. 7
    Specification → Physical Size
    Set the trailer's own unloaded (tare) Length, Width, Height, and Mass. Only needed if your organisation uses Vehicle Dimension Limits (Settings → Planning Configuration) to check the combined vehicle-and-trailer size or mass against a legal limit. Leave blank if you don't use this feature — it does not affect the 3D Visualiser.
  8. 8
    Specification → Regulatory Permits
    Add any permits applicable to this trailer — for example, a hazardous goods permit or an oversize load permit. The Planner checks these for validity (expiry) when this trailer is assigned to a trip — configurable to either warn or exclude the trailer if a permit has expired.
  9. 9
    Attribute Rules tab
    Define any rules that restrict which vehicles, products, or other entities this trailer can be used with. Leave this tab empty if this trailer has no restrictions. See Attribute Rules above for guidance on how to configure rules.
  10. 10
    Click Commit
    Saves the Trailer record. It is now available to assign to Vehicle Classes and Vehicles. Close returns without saving.

Tips & Common Mistakes

A few things to keep in mind when setting up Trailers for the first time.

  • Create all Trailer records before setting up Vehicle Classes or Vehicles. Both Vehicle Classes (for Horse and Rigid type vehicles) and individual Vehicles can reference default trailers. If you try to assign a trailer that doesn't exist yet, it won't be available in the selection list. Build your Trailer records first, then move on to Vehicle Classes.
  • Trailers apply to both Horse and Rigid type vehicles. A Rigid vehicle can carry its own load and still tow a trailer, so don't assume Trailer records are only for Horse-type tractors. Only None-type vehicles (a fixed body with no trailer capability at all) never need Trailer records.
  • You do not need a Trailer record for every physical trailer you own. If your operation plans at the class level — without tracking individual trailer units — you can create one or two representative Trailer records (e.g. Standard Flatbed, Refrigerated Trailer) and assign those to your Vehicle Classes. Individual trailer tracking is optional.
  • Double-counting capacity between the trailer and the Vehicle Class. This mainly applies to Rigid vehicles, since a Rigid already has its own capacity and may also tow a trailer. If the combined vehicle + trailer capacity is already set on the Vehicle Class, do not also add capacity to the Trailer record — the Planner will count it twice. Either set the combined capacity on the Vehicle Class and leave the Trailer capacity blank, or set them separately and let the Planner add them together. Decide on one approach and apply it consistently.
  • Enabling compartments and also setting simple Capacity. Tramm uses one or the other — not both. If compartments are defined and enabled, the Capacity field is ignored. If you later disable compartments, the simple Capacity field comes back into effect. Check which mode is active before saving to avoid a trailer with no effective capacity set.
  • Not including Length, Width, and Height in this trailer's Capacity when the 3D Visualiser is enabled. The visualiser reads these from Capacity, not from Physical Size, and uses dimensions only — not Mass. If they're missing, the visualiser cannot display the trailer, which makes it harder to visually verify loads.
