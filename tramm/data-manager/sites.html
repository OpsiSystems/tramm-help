Sites

Site Classes and Sites — the locations in your logistics network, from depots and warehouses to crossdocks and delivery points.

Sites are the locations in your logistics network — depots, warehouses, crossdocks, and delivery points. Tramm uses a two-layer system: a Site Class acts as a template that defines shared defaults such as operating hours and dwell times, and individual Sites inherit those defaults while being able to override any value that differs for that specific location. This keeps your data consistent without forcing you to repeat the same settings on every site.

What is a Site Class?

A Site Class is a template that defines shared operating hours, dwell times, and attribute rules for a group of similar sites. Rather than configuring each site individually, you set the defaults once on the class and every site in that class inherits them automatically.

For example, a Retail Delivery class might define short entry and exit durations and daytime operating hours — reflecting the reality of dropping off at a shop during trading hours. A Distribution Centre class might define longer operating hours and a higher loading rate, reflecting the heavier handling at a depot.

Any individual site can override the class defaults if that specific location differs from the norm. For instance, one particular retail outlet might have extended trading hours — you can set those hours on the site without touching the class.

The Classes concept applies across several entities in Tramm — not just Sites. See the Getting Started guide for a full explanation of how the Class and instance pattern works.

Site Class Fields

Fields available when adding or editing a Site Class.

Field Description Req Opt Override
Name The display name of the class. Describes the type of site it represents (e.g. "Distribution Centre", "Retail Delivery Point"). ✓
Operating Hours Default working hours for all sites of this class. Individual sites can override this if they have different hours. ✓
Entry Duration Time added to the start of each stop at sites of this class — arrival dwell time (check-in, setup). Used in trip time calculations. ✓
Exit Duration Time added to the end of each stop at sites of this class — departure dwell time (sign-off, close). Used in trip time calculations. ✓
Attributes Custom attributes inherited by all sites in this class. Used for matching and filtering. ✓
Restrictions Rules that control which vehicle types or product types can service sites in this class. ✓

What is a Site?

A Site is an individual location in your network — a depot, warehouse, crossdock, or delivery point. Each site references a Site Class to inherit its defaults, and can override any of those defaults if the specific location requires different values.

Every site has a physical address and GPS coordinates — coordinates are used for route distance and time calculations, and for automatically assigning the site to the correct Region. Sites can also carry contact information, operational instructions for drivers, and a link to a specific client if the site is client-specific.

Site Fields

Fields available when adding or editing a Site.

Field Description Req Opt Override
Name The display name of the site as it appears throughout Tramm. ✓
Code A short unique identifier for the site, used in imports and integrations. ✓
Site Class The class this site belongs to. Sets the default operating hours, entry/exit durations, and attribute rules. Strongly recommended — a site without a class has no defaults. ✓
Location / Address The physical address of the site. Used for route planning and displayed on maps. ✓
GPS Coordinates Latitude and longitude. Required for accurate route calculations and for automatic region assignment. Without coordinates, the planning engine cannot route to this site. ✓
Type Site type label (e.g. Depot, Customer, Crossdock). Controlled by Entity Types in Data Manager. ✓
Operating Hours If set, overrides the Site Class operating hours for this site only. Leave blank to use the class default. ✓
Entry Duration If set to a non-zero value, overrides the Site Class entry duration for this site. Use when this site takes longer or shorter to check in than the class default. ✓
Exit Duration If set to a non-zero value, overrides the Site Class exit duration for this site. ✓
Loading Rate Site-specific loading/unloading speed. Overrides any class or product-level loading rate when set. ✓
Regions The geographic region(s) this site belongs to. Used for Lane-based tariff pricing. Can be assigned manually or automatically based on GPS coordinates. ✓
Client Link this site to a specific client if it is a client-dedicated location (e.g. a customer's warehouse). ✓
Contact Info Phone number, email, and address contact details for the site. ✓
Instructions Free-text operational notes visible to planners and drivers — access codes, delivery instructions, special requirements. ✓
Attributes Site-specific custom attributes, in addition to those inherited from the Site Class. ✓

✓ in the Opt column marked in teal = Recommended (important even if not strictly required)

How Override Logic Works

For Entry Duration, Exit Duration, and Operating Hours, the Site value takes priority over the Site Class value — but only if it is actually set. If the site's value is zero (for durations) or blank (for operating hours), the system automatically falls back to the Site Class value.

Is Entry Duration set on the Site (non-zero)?
Yes
Use the Site's Entry Duration
No / Zero
Use the Site Class Entry Duration

The same logic applies to Exit Duration and Operating Hours. This means you only need to fill in these fields on a site when it genuinely differs from its class — leave them blank and the class values apply automatically.

Adding a Site Class

Create Site Classes before adding sites. Even if you start with only one class, the class concept makes it easy to update shared settings across many sites later.

  1. Open Data Manager and select Site Classes from the navigation.
  2. Click Add in the toolbar.
  3. Enter a name that describes the type of site — for example, Retail Delivery, Distribution Centre, or Crossdock.
  4. Set Operating Hours for this class — the default hours during which sites of this type are accessible.
  5. Set Entry Duration and Exit Duration — the time it typically takes to arrive at and depart from sites in this class.
  6. Add any shared Attributes or Restrictions if applicable to all sites in this class.
  7. Click Save.

Adding a Site

Before adding sites, make sure your Site Classes are already set up. The Site Class selection is one of the first fields in the form and sets several defaults for the rest of the form.

  1. Open Data Manager and select Sites from the navigation.
  2. Click Add in the toolbar.
  3. Enter the site name and, if used, a short code.
  4. Select the Site Class. This sets the default operating hours, entry duration, and exit duration for the site.
  5. Select the site type if applicable.
  6. Enter the Location — address and GPS coordinates. Coordinates are used for route calculations and for automatically assigning the site to the correct Region.
  7. Override Operating Hours, Entry Duration, or Exit Duration only if this site differs from its class defaults. Leave these at zero or blank to inherit from the class.
  8. Assign Region(s) if not using automatic region assignment from GPS coordinates.
  9. Link a Client if this is a client-specific site.
  10. Add Contact Info and any operational Instructions for drivers or planners.
  11. Click Save.

Tips & Common Setup Mistakes

Create Site Classes before adding sites

Even if you start with a single class, the class concept makes it easy to update shared settings across many sites later without editing each one individually.

Enter GPS coordinates accurately

Coordinates are used for route distance and travel time calculations, and for automatically assigning sites to Regions. An inaccurate coordinate can result in incorrect distances or a site ending up in the wrong Region.

Set meaningful Entry and Exit Durations

These values directly affect trip timing in the Planner. An incorrect dwell time leads to unrealistic schedules — trips will appear faster or slower than they are in practice.

Common mistake: Entry and Exit Duration left at zero on both the site and its class

If neither the site nor its class has a duration set, the Planner will calculate zero dwell time at that stop. Planned trips will appear faster than they are in practice, and driver schedules will be unrealistic from day one.

Common mistake: Not assigning a Region

If you use Lanes for tariff pricing, sites must be assigned to a Region for the Lane pricing to apply correctly. A site with no Region will not match any Lane, and trip costs may be calculated incorrectly or not at all.
