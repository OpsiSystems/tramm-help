A Site is an administrative record for a place in your logistics network — a depot, warehouse, crossdock, or delivery point. It defines what can happen there (operating hours, restrictions, contact details) — not where it physically is; that's stored separately in a Location (see What is a Location? below). Tramm uses a layered system: a Site Class acts as a template that defines shared defaults such as operating hours and dwell times, and individual Sites inherit those defaults while being able to override any value that differs for that specific location. This keeps your data consistent without forcing you to repeat the same settings on every site.

Site Class — the template
Defines shared defaults for a group of similar sites.

  • Entry and exit durations (default)

Site — the individual location

What is a Site Class?

A Site Class is a template that defines shared operating hours, dwell times, and attribute rules for a group of similar sites. Rather than configuring each site individually, you set the defaults once on the class and every site in that class inherits them automatically.

For example, a Retail Delivery class might define short entry and exit durations and daytime operating hours — reflecting the reality of dropping off at a shop during trading hours. A Distribution Centre class might define longer operating hours and a higher loading rate, reflecting the heavier handling at a depot.

Any individual site can override the class defaults if that specific location differs from the norm. For instance, one particular retail outlet might have extended trading hours — you can set those hours on the site without touching the class.

The Classes concept applies across several entities in Tramm — not just Sites. See the Getting Started guide for a full explanation of how the Class and instance pattern works.

Think of a Site Class like a standard operating specification for a type of location — the equivalent of a specification sheet that describes how a particular category of site works. You define the operating hours, dwell times, and restrictions once on the class, and every site you create from that class inherits those settings automatically. You only need to record what is different on an individual site: its address, GPS coordinates, or any operational detail that makes it unique. A "Retail Delivery" class might cover dozens of similar customer sites, all sharing the same dwell times and operating hours, with exceptions noted only where they exist.

Fields available when adding or editing a Site Class.

Field Description Req Opt Override
Name The display name of the class. Describes the type of site it represents (e.g. "Distribution Centre", "Retail Delivery Point"). ✓

What is a Site?

A Site is an individual location in your network — a depot, warehouse, crossdock, or delivery point. Each site references a Site Class to inherit its defaults, and can override any of those defaults if the specific location requires different values.

Every site has a physical address and GPS coordinates — coordinates are used for route distance and time calculations, and for automatically assigning the site to the correct Region. Sites can also carry contact information, operational instructions for drivers, and a link to a specific client if the site is client-specific.

What is a Location?

A Site is an administrative record — it defines what you can do at a place (its code, attributes, restrictions, contact details). Where that place actually is — the address, latitude, and longitude — is stored in a separate entity called a Location.

Every Site has a Location, but you have two ways to set it up:

Inline Location
A Location that belongs to this Site alone — you enter the address and GPS coordinates directly on the Site. This is the normal choice for a standalone site, such as a shop that isn't inside a larger complex.
  • Has its own entry and exit duration
  • Not shared with any other site
Reference Location
A standalone Location record that multiple Sites can point to. Use this when two or more sites genuinely share the same physical place — for example, two shops inside the same mall.
  • Entry and exit duration is charged only once for the whole location
  • Each site under it still adds its own turnaround time

For example, a stop called "Rosebank" might contain two sites — "Site 1" and "Site 2" — that both reference the same Location. On the solver, this produces one entry duration and one exit duration for the whole stop, plus each site's own turnaround time in between. If those two sites instead had their own inline locations, each would be entered and exited separately.

There are three reasons to use a standalone Location record: (1) sharing one physical place between multiple sites, as above; (2) setting up loading bays and docks, which are configured at the Location level via the Loading Bay Manager; (3) marking a Location as a rest/break stop, which can then be assigned to a route via Restop Assignment so a route's rest stop happens at a specific place instead of wherever the routing engine picks arbitrarily.
Moving from Plato? Plato required a separate "map point" record for every single site. Tramm's inline Location removes that requirement — a normal site with its own address needs nothing extra. Only set up a standalone Location record when you actually want to share it between sites, or need loading bays or a rest stop.

How Override Logic Works

For Entry Duration, Exit Duration, and Operating Hours, the Site value takes priority over the Site Class value — but only if it is actually set. If the site's value is zero (for durations) or blank (for operating hours), the system automatically falls back to the Site Class value.

Is Entry Duration set on the Site (non-zero)?
Yes
Use the Site's Entry Duration
No / Zero
Use the Site Class Entry Duration

The same logic applies to Exit Duration and Operating Hours. This means you only need to fill in these fields on a site when it genuinely differs from its class — leave them blank and the class values apply automatically.

Adding a Site Class

Create Site Classes before adding sites. Even if you start with only one class, the class concept makes it easy to update shared settings across many sites later.

  1. Open Data Manager and select Site Classes from the navigation. Click Add in the toolbar.
  2. Basic Info tab: Enter the class Name — something that describes the type of site it represents, for example Retail Delivery, Distribution Centre, or Crossdock. The ID is auto-generated. The External ID is generated automatically too, from a template configured in Settings. Add a Description if needed. The Groups field assigns this class to a Group for shared-resource organisation — see Groups & Shared Resources for how this works. This is different from Settings → Partitions. Leave blank in a standard single-organisation setup.
  3. Specification → Entry/Exit Duration: Set the default Entry Duration and Exit Duration in hours and minutes. These are the typical dwell times for arrival and departure at sites of this class — every site in the class will inherit these values unless overridden on the individual site.
  4. Specification → Attributes: Add any shared attributes that all sites in this class should carry automatically. Leave blank if no shared attributes are needed at this stage.
  5. Operating Hours tab: Set the default operating days and time windows for sites of this class.
  6. Attribute Rules tab: Add attribute rules if needed — for example, to restrict which vehicle types or product types can service sites in this class.
  7. Click Commit.

Adding a Site

Before adding sites, make sure your Site Classes are already set up. The Site Class is selected in the first Specification sub-section and sets several defaults for the site.

  1. Open Data Manager and select Sites from the navigation. Click Add in the toolbar.
  2. Basic Info tab: Enter the site Name (required). The ID is auto-generated. The Groups field assigns this site to a Group for shared-resource organisation — see Groups & Shared Resources for how this works. Leave blank in a standard single-organisation setup.
  3. Specification → Links: Select the Site Class (recommended). This sets the default operating hours, entry/exit durations, and attribute rules for the site. Optionally link a Client if this is a client-specific location.
  4. Specification → Type: Select the site type if applicable — for example, Depot, Customer, or Crossdock. Types are configured in Entity Types.
  5. Specification → Instructions: Add any operational notes — access codes, delivery instructions, or special requirements for drivers or planners.
  6. Specification → Location: By default you enter the site's own address and GPS coordinates directly — this creates an inline Location just for this site. If this site shares its exact physical place with another site (for example, two shops in the same mall), use the Location Ref chooser instead to point both sites at the same shared Location record — see What is a Location? above. The Auto Allocate To Region checkbox is on by default — leave it checked to have the system assign the site to a Region automatically.
  7. Specification → Region Allocation: If you are not using automatic region allocation, manually assign the site to one or more Regions here.
  8. Specification → Linked Vehicle Classes: Link the Vehicle Classes permitted to service this site. Only vehicles in these classes will be considered for stops here during planning. Leave blank to allow all classes.
  9. Specification → Durations: Override the Entry Duration or Exit Duration only if this specific site's dwell time differs from its Site Class default. Leave at zero to inherit from the class.
  10. Specification → Loading Rate: Override the loading rate if this site handles goods at a different rate from the class or product default.
  11. Specification → Attributes: Add any site-specific attributes not already inherited from the Site Class.
  12. Operating Hours tab: Override the operating hours only if this site's hours differ from its Site Class. Leave blank to inherit from the class.
  13. Contact Info tab: Add the site contact details — contact name, type, and details.
  14. Attribute Rules tab: Add any site-specific attribute rules if needed.
  15. Click Commit.

Tips & Common Setup Mistakes

Create Site Classes before adding sites

Even if you start with a single class, the class concept makes it easy to update shared settings across many sites later without editing each one individually.

Enter GPS coordinates accurately

Coordinates are used for route distance and travel time calculations, and for automatically assigning sites to Regions. An inaccurate coordinate can result in incorrect distances or a site ending up in the wrong Region.

Set meaningful Entry and Exit Durations

These values directly affect trip timing in the Planner. An incorrect dwell time leads to unrealistic schedules — trips will appear faster or slower than they are in practice.

Common mistake: Entry and Exit Duration left at zero on both the site and its class

If neither the site nor its class has a duration set, the Planner will calculate zero dwell time at that stop. Planned trips will appear faster than they are in practice, and driver schedules will be unrealistic from day one.

Common mistake: Not assigning a Region

If you use Lanes for tariff pricing, sites must be assigned to a Region for the Lane pricing to apply correctly. A site with no Region will not match any Lane, and trip costs may be calculated incorrectly or not at all.
